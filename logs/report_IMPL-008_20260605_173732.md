## 1. 何をやったか(一言)
UI の顔トリミング(CropDialog)が顔をきつく切りすぎて、顔データが入らない問題。
フロント側のコードを調べ、「どう直すのが一番確実か」を見極めて、実装方針を1つに
絞り込んだ。コードはまだ書いていない(承認待ち)。

## 2. 分かったこと(現状)
- トリミング画面は react-easy-crop。ユーザーは最大3倍までズームして顔に寄れる。
  確定すると、その枠だけを 1024×1024 に切り出して reference として送る。
- **顔の大きさを一切見ていない**。「顔を中央に」と促されるので顔ドアップになり、
  生成側でさらにクロップ → 顔検出(facexlib)が余白不足で失敗 → 顔データ無し。

## 3. 重要な発見 — これは「バンド(上限と下限の両方)」問題
- 実証値「0.22/0.30=失敗、0.40/0.55/0.70=成功」と IMPL-007(余白あり原画=成功/
  ドアップ=失敗)を合わせると、顔検出が通る「顔/枠の比率」には**上限も下限もある**:
  - 顔が大きすぎ(ドアップ) → 失敗
  - 顔が小さすぎ(グレー余白で顔が極小) → 失敗
  - **成功帯 ≒ 顔が枠の 0.40〜0.70、安全目標 ≒ 0.50**。
- 意味: 「とにかく広げればいい」ではない。**実画像(髪・首・肩)を含めて顔を約50%に
  “着地”させる**のが要件。グレー余白は不可(実証)。

## 4. 案の判断(a vs b)
- (a) ズーム上限を絞る: 最小実装だが、顔サイズを知らないので「顔≤50%」を保証できない。
  → 不採用(確実でない)。
- (b) 確定後に枠を中心拡張し、元画像の実コンテキストを取り込む: **これを推奨**。
  - 最も実装が容易(切り出し矩形の後処理だけ・新規部品不要・フロントのみ・
    localhost:3000 で即反映)。
  - 要件に直接効く(ユーザーの枠≒顔とみなし、出力で顔を約50%に着地。髪/肩も同梱)。
  - 残リスク: もともと緩く切った人は拡張で顔が小さくなりすぎる可能性 →
    拡張倍率の選定(初期値1.7)とクランプで実害最小化。完全保証ではない。

## 5. 反映チャネル(確認済み)

- 反映 = ①拠点1の .tsx 編集で localhost:3000 即リロード(PO 確認可)→ ②GitHub(aibo_v8)push。
- **.py の 4拠点 Drive 同期は不要**(フロント変更・Colab の .py ではない)。Colab 再 run も不要。
