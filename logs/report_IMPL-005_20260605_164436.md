# 報告 IMPL-005 — 観測系の信頼性修正(測定の順序汚染を消す)

- 日時: 2026-06-05 16:44
- 担当: 実装くろうど
- 由来: RECON-006c 案1(昨日 id_embeds=無 の真因追跡中、観測値が前回の痕跡で
  汚染され3回誤判定した、その根本対策)

## 1. 何をやったか(一言)
「観測の値が、別の生成の痕跡で上書きされて嘘をつく」問題を根本から潰した。
これからは各生成の `[OBS-SUMMARY]` が、その生成だけの本当の値を映す。

## 2. なぜ起きていたか(平易に)
顔データを作る部品(PuLIDExtractor)は1個を使い回している。その部品に
「前回どんなエラーだったか / 顔を何個見つけたか」をメモする欄があるが、
(a) そのメモ欄は使った時に初めて作られる作りで、(b) 生成のたびに消されなかった。
そのため、手動で1回うまく抽出すると「成功」のメモが残り、その後 UI から生成して
失敗しても、サマリが古い「成功」メモを読んでしまう、という順序汚染が起きていた。
→ 「無」なのに理由が前回の成功痕跡を指す、といった誤判定の温床。

## 3. 直した内容(2点・観測性のみ・核非接触)
1. 03_identity_engine.py の PuLIDExtractor.__init__ に観測メモ欄の初期化を追加:
   `self._last_extract_error = None` / `self._last_face_count = None`
   → 実行前から必ず定義され、未定義参照や作られる前の読み取りが消える。
2. 05_orchestrator.py の generate() で、顔データ準備(prepare)の直前に
   その生成用のリセットを実施:
   共有部品の `_last_extract_error` / `_last_face_count` を None に戻してから抽出に入る。
   → 各 `[OBS-SUMMARY]` は「その生成の真値」だけを反映する。
