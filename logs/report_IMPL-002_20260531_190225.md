## 1. 何をやったか(一言)
外国人化の真因だった「Drive 越しにモデルを読む経路」を notebook 起動セルから**撤去**し、
モデルを **HF Hub から Colab の高速ディスク(/content)へ直接ダウンロード**する方式に変えた。
これで「途中で切れたファイルをそのまま読んで外国人になる」事故が**構造的に起きなくなる**。

## 2. 変更内容（aibo_v7_colab.ipynb の起動セル cell `30a3d9c9` のみ）

### 撤去した事故経路（実コード）
- `tar pipe（180秒タイムアウト）`で Drive→/content へ一括コピーするブロック。
- タイムアウト時に /content を消して **Drive 直結 symlink** を張る fallback（= FUSE 越し巨大読み込みの元凶）。
- それに付随する `_du_bytes` / `CACHE_SYNC_TIMEOUT` / サイズ比較ロジック。
- `HF_HUB_ENABLE_HF_TRANSFER=1`（deprecated 警告源）。高速化は既定の hf_xet に委ねる。

### 残した正しい設定
- HF cache の置き場を /content(NVMe) に固定する env（`HF_HOME` 他）と `/root/.cache/huggingface → /content` の
  symlink（NVMe 向け・Drive ではない）。
- Drive mount 自体（コード AIBO_ROOT の読み込みに必要。モデルの一次ソースには使わない）。
- `sync_back_to_drive()`（手動呼び出しのみ・起動経路外。今回は不使用＝案C には踏み込まない）。

### 追加した処理
- **HF token 注入（Phase 1.4）**: `userdata.get('HF_TOKEN')` → `huggingface_hub.login()`。
  token は**コードに直書きせず・ログにも出さない**。token 不在時は
  `⚠️ [CASE-A] HF_TOKEN 未設定。gated モデル… は失敗します` を**明示出力**（silent fail なし）。
- **HF→/content 直 DL（Phase 1.5）**: `snapshot_download` で 8 repo を取得（default cache-dir 方式）。
  - gated（token要）2: `black-forest-labs/FLUX.1-dev`, `…/FLUX.1-Redux-dev`
  - public 6: `nunchaku-tech/nunchaku-flux.1-dev`, `mit-han-lab/svdq-int4-flux.1-fill-dev`,
    `Shakker-Labs/FLUX.1-dev-ControlNet-Union-Pro-2.0`, `XLabs-AI/flux-ip-adapter`,
    `guozinan/PuLID`, `ByteDance/Hyper-SD`
  - DL 失敗（gated の 401/403 等）は握りつぶさず `❌ [CASE-A] FAIL: <repo> :: <例外>` を出して**即停止**。

### C0（IMPL-001）は無変更
- snapshot_download 後、各 from_pretrained 直前に既存の C0 検証ゲートが走り、出口を守る（今回 C0 は触らない）。
