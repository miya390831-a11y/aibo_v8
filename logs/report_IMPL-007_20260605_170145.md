## 1. 何をやったか(一言)
UI で顔ドアップの reference を入れると顔データ(id_embeds)が入らず外国人寄りになる、
その最後の穴を塞いだ。顔が検出できなかった時、**余白のある元の画像でもう一度だけ
試す**ようにして、ドアップ画像でも顔検出が通るようにした。

## 2. 真因(実証済み・おさらい)
- 生画像(余白あり)を入れて generate すると id_embeds=有・PuLID 成功(IMPL-006 で実証)。
  → generate 経路・extractor・PuLID は正常。
- UI 経由だけ id_embeds=無。差は UI の CropDialog が作る「顔ドアップ画像」。
- ドアップ → generate 内の snipe で二重クロップ → 顔が画面いっぱい → 顔検出器(antelopev2)が
  周囲マージン不足で未検出 → id_embeds が入らない。
- = 犯人は「UI クロップ + snipe の二重クロップによる顔未検出」。

## 3. 直した内容(案1・glue のみ・PuLID 核非接触)
- ファイル: `05_orchestrator.py`(このファイルのみ変更)
- 場所: `generate()` の identity 準備直後、`result.pulid_used` 代入の直前。
  - `05_orchestrator.py:512-526` に原画リトライブロックを追加。
- ロジック:
  1. snipe 後画像で prepare → `id_embeds` が入らなかった、かつ reference 画像がある場合のみ、
  2. snipe していない元の画像(`id_cfg.reference_image`・余白あり)で **1回だけ** 再 prepare。
  3. それで id_embeds が取れれば採用(`pulid_used=True` になる)。取れなければ警告を出して
     これまで通り PuLID 無しで生成継続。
- コピー作法は既存(05:487/495)と同じ `IdentityConfig(**asdict(id_cfg))` を踏襲。
  `asdict` は既に import 済み(05:39)なので追加 import 不要。
