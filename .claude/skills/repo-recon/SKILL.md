# 偵察・調査・設計案起草の作法

特殊部隊の調査ミッション用。調査と設計"案"までを質高く、ただし決定はしない。

## 成果物
- 調査ログ → `docs/research/<topic>_<日付>.md`
- 設計案  → `docs/design/<topic>_<日付>.md`

## 設計案の要件(必須)
- **複数案**(最低2つ)を出す。単一案で確定しない。
- 各案に: 効果見込み / リスク / 実装コスト / **厳守ルール適合チェック** を付ける。
- **出典**(リポ URL・該当ファイル/行)を残す。
- 推奨を書いてよいが、あくまで「案」。**決定は司令部**。

## 調査のやり方
- 規模が見合えばワークフローで並列展開し、各発見を独立検証してから報告(自己検証)。
- 一次情報優先: リポの実装本体・issue/PR・公式 docs・論文。フォーラムは裏取りのみ。
- AIBO の主戦場に着目: PuLID embedding 集約 / Nunchaku low-rank branch / Hyper-FLUX /
  diffusers FLUX 系 API。

## 禁止(特殊部隊特則)
- 設計の確定(司令部の領分)。
- 繊細な核心部(Setting A / PuLID / 量子化核)の改修。読むのは可。
- **ACE++ の AIBO への導入・移植**(調査で読むのは可、持ち込みは禁止)。
- 偵察結果を AIBO 本体に勝手に組み込むこと(組み込みは司令部 + 実装くろうど)。

## コスト規律
スコープを絞る。`/usage` で消費確認、想定超で `/workflows` 停止 → 司令部に報告。
