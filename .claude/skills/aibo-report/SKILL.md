# 報告の作法(司令部向け)

司令部(CTOくろうど + みやちん)が読む報告。生の技術ログを流さず、判断材料として書く。

## 置き場所・命名
- `logs/report_<タスク番号>_<timestamp>.md`(例: logs/report_002_20260528_1530.md)

## 構成(専門用語を避けて)
1. 何をやったか(一言)
2. 結果(直ったか / 数値 / 再現条件)
3. 残課題
4. **要・司令部判断の事項**(あれば「保留」と明記し、勝手に先へ進めない)
5. 次の一手の提案(あれば。決定は司令部)

## ルール
- 平易な言葉で。みやちんが生ログを読まなくて済むように要約する。
- 事実・数値・再現条件は具体的に(次の作戦会議の材料になる)。
- 不確実なことは「不確実」と正直に書く。盛らない。「できた風」にしない。
- 完了条件を満たしていない項目を「完了」と書かない(phase-gate 参照)。
